- **Issue #6 — Moteur de lecture (react-native-track-player)** (2026-07-03) : intégration de `react-native-track-player` **5.0.0-alpha0** avec un module `src/player/` (service headless `service.ts` pour les commandes distantes, `setup.ts` init idempotente + capacités, `track.ts` LocalTrack→Track résolvant URI (`Asset.getUri()`) + tags/pochette, `PlayerProvider.tsx` exposant les actions play/toggle/next/prev/seek et `usePlayback.ts` l'état réactif via les hooks RNTP). Entry point custom `index.js` (enregistre le service, garde web), UI câblée (tap piste => file + lecture dans `app/(tabs)/index.tsx`, `MiniPlayer` et `now-playing` sur l'état réel + seek au tap) ; web étant hors périmètre (Android only), RNTP tirant `shaka-player`, on stub RNTP sur le web (`metro.config.js` + `src/player/trackPlayer.web-shim.js`) et on passe `web.output` à `single` (le prerender statique était incompatible). **Choix de version (important)** : la stack impose la New Architecture (Reanimated 4), or RNTP **4.1.2 (MIT)** est ancienne archi et crashe au runtime (TurboModule interop : « returnType == void iff synchronous ») ; la v5 **stable** est republiée sous `@rntp/player` mais en **licence propriétaire** (gratuite usage perso, payante en pro). On reste donc sur `react-native-track-player@5.0.0-alpha0`, dernière version **libre (MIT)** compatible new arch (vrai TurboModule, `NativeTrackPlayerSpec`). ⚠️ **Choix assumé mais fragile** (release unique, non maintenue) : si l'alpha casse un jour (bump Expo/RN, bug de lecture), ne pas s'acharner à la patcher, migrer vers `@rntp/player` 5.6.0+ (stable, gratuit usage perso mais proprio) ou `expo-audio` (libre/stable, first-party ; gère écran verrouillé + notif via `setActiveForLockScreen` / `enableBackgroundPlayback` dès le SDK 56, mais seulement play/pause + seek — pas de boutons piste suivante/précédente sur la notif, contrairement à RNTP qui est file-native). ⚠️ Build natif **sous JDK 21** obligatoire : jenv peut laisser `JAVA_HOME` sur un JDK plus récent qui casse la config CMake/prefab (« restricted method in java.lang.System ») ; forcer `JAVA_HOME` sur openjdk@21 pour un `gradlew` direct (`expo run:android` en shell interactif prend déjà 21). Lint/format/typecheck/export web OK.
